## What this role usually means

Full-stack engineers ship across client and server: UI, APIs, data, auth, and usually some DevOps. They are judged on being useful on both sides of the HTTP boundary, not on being the deepest specialist on either.

## What you actually did on FitGenius

FitGenius is a pre-launch consumer fitness product: iOS and Android (Expo / React Native), Firebase backend (~64 Cloud Functions, Firestore rules, IAP verification, Gemini AI), marketing site (Vite/React), app/legal/admin hosting, store-submission runbooks, and a legal/compliance suite. You were the founding technical partner — one person owning product, code, cloud, QA packets, and founder enablement from roughly May through September 2026.

Client: Expo Router app, React 19 marketing site, Tailwind, admin SPA. Server: Cloud Functions, Firestore, Storage, scheduled jobs, IAP webhooks. Glue: CI, Firebase Hosting dual targets, legal HTML generation, EAS. You regularly shipped features that touched mobile + functions + rules in one change.

## How that work applies to **Full-Stack Engineer**

This is one of the two or three titles that FitGenius *is*. Full-stack at a startup means exactly this loop. Weakest full-stack slice is traditional server-rendered web apps and SQL/Postgres — your data layer is Firestore.

## Strengths a hiring manager can credit

- Mobile + web + functions in one person
- Auth, files, jobs, hosting
- Ability to debug across layers (client callable errors, rules, Crashlytics)

## Gaps versus a typical hiring bar

- No classic REST+Postgres monolith
- Frontend is RN-first; CSS-system depth is secondary
- No Kubernetes

## How to talk about it

Say 'TypeScript full-stack: React Native client, Firebase/Node functions, React marketing site.' Offer Firestore as a document store you modeled carefully, not as a lack of SQL skill if you have SQL elsewhere.
