## What this role typically requires

Build line-of-business or customer-facing applications: screens, forms, integrations, and deployable artifacts. Often JavaScript/React, sometimes .NET/Java. Success is a working app used by real people.

## What you have done in this project

You built the actual application the practice uses for acquisition: multi-section SPA, form validation, success/error UX, external EHR scheduling, mobile dock, and a documented deploy path. The redesign added reusable UI primitives (Button, Card, FormFields, FAQItem) and hooks (`useActiveSection`, `useReveal`, `usePrefersReducedMotion`).

## How that work applies to Application Developer

Application Developer is the cleanest “I built the app” title. This is a complete application with user journeys (browse → book, browse → contact, crisis → hotline). You handled browser constraints (touch, reduced motion, noscript fallback, PWA manifest) that application developers hit daily.

## Gaps versus a typical hiring bar

No authenticated app, no CRUD against a database, no role-based screens. Many “application developer” jobs are internal tools with data models. You have the UI/integration half, not the persistence half.
